# Plan: Fix GraphQL name collisions in tracking

> **Status:** Historical / Non-Authoritative

## Status

**RESOLVED** on 2026-08-29: the colliding operations were renamed with `name` overrides — `workoutSessionFindAll`/`workoutSessionFindOne`, `extraSessionFindAll`/`extraSessionFindOne`, `dayLogFindAll`/`dayLogFindOne`. `removeExtraSession` (returns `Boolean`) remains as an intentional exception. This plan is kept for traceability and historical review only; the authoritative source of truth is the Spec and the Code.

---

## Implementation (2026-08-29)

The agreed convention was applied: **the TypeScript methods stay as they are** (`findAll` / `findOne`), but the **`name` override** of the GraphQL operations was changed to eliminate the collision. `removeExtraSession` (returns `Boolean`) is kept as an intentional exception.

Resolvers touched:
- `workout-session.resolver.ts` → `workoutSessionFindAll` / `workoutSessionFindOne`
- `extra-session.resolver.ts` → `extraSessionFindAll` / `extraSessionFindOne`
- `day-log.resolver.ts` → `dayLogFindAll` / `dayLogFindOne`

Verification: `npm run build` ok · unit 59 suites / 584 tests ok · e2e 23 suites / 126 tests ok · `npm test` ok. The existing e2e and specs did not reference the old names (they used the week-log operations or the nested `workoutSession`/`extraSession` fields of the `days[]` object), so they required no changes.

## Original context (historical)

## Problem

Several tracking operations expose the **same GraphQL name** for distinct operations. In the schema generated by Apollo (`autoSchemaFile: true`), the second definition with the same name **hides the first**, so one of the two operations becomes inaccessible / unpredictable for the client.

The collided operations (all with explicit `name` override):

| Resolver | findAll operation | findOne operation | Conflict |
|----------|-------------------|-------------------|----------|
| `workout-session` | `workoutSession` | `workoutSession` | duplicate |
| `extra-session` | `extraSession` | `extraSession` | duplicate |
| `day-log` | `dayLog` | `dayLog` | duplicate |

Additional cases:

- `removeExtraSession` returns `Boolean` (unlike the rest of `remove*`, which return the entity): inconsistency, not a name collision. **Kept as an intentional exception.**

---

## Impact / Considerations

- It is a **breaking change in the GraphQL API**: clients calling `workoutSession`/`extraSession`/`dayLog` (without an `id` argument to list, or with an `id` for a single record) must update to the new names.
- **Angular frontend (other repo):** locate and migrate the tracking GraphQL calls that use those names.
- It does not affect `week-log` (its operations are already unique: `findAll`/`findOne` without override, they do not collide).

## Decision notes

- **Chosen naming convention:** `<entity>FindAll` / `<entity>FindOne` (e.g. `workoutSessionFindAll`). The plural/`ById` variant (`workoutSessions` / `workoutSessionById`) was discarded.
- **`removeExtraSession` → `Boolean`:** kept as an intentional exception (not unified to return the entity).
